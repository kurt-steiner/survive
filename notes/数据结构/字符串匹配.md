# KMP 算法

![image](../images/字符串匹配.png)

我们这样描述 **KMP** 算法，

```julia
function match(string::String, pattern::String)::Int
```

整个KMP算法中，会

1. 通过 `pattern` 生成部分匹配表
2. 匹配过程中，对 `pattern` 的移动量通过
    `already_matched - pm(alread_matched)` 求得

## 部分匹配表

举个例子，对于模式串 **abcac** ，我们有部分匹配表的生成过程

|字符串子串|前缀|后缀|max(前缀，后缀) 长度|
|:--:|:--:|:--:|:--:|
|a | null| null | 0 |
|ab | a | b | 0 |
|abc | a,ab |c,bc | 0 |
|abca| a,ab,abc | bca, ca, a |1 |
|abcac| a, ab, abc, abca | bcac, cac, ac, c| 0 |

于是有 部分匹配表

|编号| 1 | 2 | 3 | 4| 5|
|:--:|:--:|:--:|:--:|:--:|:--:|
|char |a |b |c|a |c |
|pm | 0 | 0 | 0 | 1| 0 |

## 基本匹配过程

在调用 `match("ababcabcacbab", "abcac")` 时，当匹配进行到 `pattern[index]` 时发现匹配失败了，有

|主串| a |b | a| b| c|a |b |c |a | c| b | a |b |
|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 子串|a |b |c | a| c| | | | | |  |  | |

此时，`1-based` 的索引为 3 ，对应已匹配的 **pm** 为 `pm[2] = 0`，需要移动

```julia
movement = index - 1 - pm[index - 1]
```

## 改进匹配过程 `next`

在前面我们谈到

```julia
movement = index - 1 - pm[index - 1]
```

其中有两次 `index - 1`，我们可以将 **pm** 表往右移动，缺失值填 **-1**，有

|编号| 1 | 2 | 3 | 4| 5|
|:--:|:--:|:--:|:--:|:--:|:--:|
|char |a |b |c|a |c |
|pm | -1 | 0 | 0 | 0| 1 |

我们 `pm` 重新命名，变为 `next` ，现在有

|编号| 1 | 2 | 3 | 4| 5|
|:--:|:--:|:--:|:--:|:--:|:--:|
|char |a |b |c|a |c |
|next | -1 | 0 | 0 | 0| 1 |

这样以后，我们重新描述移动过程，有

```julia
movement = index - 1 - next[index]
```

这样可以少进行一次计算

**补充**

1. 为什么前面缺失的值填-1？  
因为如果查找字符串失败，最终返回的索引是-1
2. pm表往右移动时，最后那个值丢掉不要紧吗？  
不要紧，因为匹配到这个程度时，在原来的匹配过程中，有

    ```julia
    movement = index - 1 - pm[index - 1]
    ```

    始终访问不到 最后一个 `pm` 的值

## 再次改进匹配过程 `nextval`

在教材中，对 `next` 数组的生成又进行了一次改进，有

```julia
if pattern[index] == pattern[next[index]]
    nextval[index] = next[next[index]]
else
    nextval[index] = next[index]
end
```
